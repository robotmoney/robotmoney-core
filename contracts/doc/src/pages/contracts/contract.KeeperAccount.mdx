# KeeperAccount

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/686fb6eee37ebea70d3c4d3ec214392afc74d9f7/contracts/KeeperAccount.sol)

**Title:** KeeperAccount

The one `KEEPER_ROLE` holder (E56, D36): a team-operated smart account. Its owners add and remove bot keys
without the fund timelock, so a broken or leaked bot key is replaced in one transaction and the fund is
not left without a keeper for the length of a timelock delay. A bot key can only forward a call through
`execute`. The account holds no funds and no role other than `KEEPER_ROLE`, so a forwarded call can only
do what that role allows (`settle` on the queue, `step` on the rebalancer). A bot key cannot change the
owners or the bot keys, because `execute` never targets the account itself.

`owners()` and `botKeys()` are the views the verifier reads (publish-contracts verify/fund.ts), so the
deploy tool can compare them with the sheet.

## Errors

### NotOwner

The caller is not an owner.

```solidity
error NotOwner();
```

### NotBotKey

The caller is neither a bot key nor an owner.

```solidity
error NotBotKey();
```

### InvalidAccount

A zero address, a duplicate, or an empty owner set.

```solidity
error InvalidAccount();
```

### LastOwner

The last owner cannot be removed: nobody could rotate a bot key after that.

```solidity
error LastOwner();
```

### SelfCall

`execute` cannot call the account itself.

```solidity
error SelfCall();
```

### CallFailed

The forwarded call reverted. `data` is its revert data.

```solidity
error CallFailed(bytes data);
```
