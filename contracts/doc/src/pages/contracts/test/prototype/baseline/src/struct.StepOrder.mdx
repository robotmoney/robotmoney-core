# StepOrder

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/d51a8ed56dc72ae8662acc53f88fb090d86e44cb/contracts/test/prototype/baseline/src/FundTypes.sol)

The order the Rebalancer sends to `RobotMoneyFund.executeStep` (§5.3 steps 4 to 7).
Every field is computed by the Rebalancer from chain state (RB-2).

```solidity
struct StepOrder {
    uint256 sellIndex;
    uint256 buyIndex;
    uint256 notionalUsdc;
    uint256 minSellUsdcOut;
    uint256 minBuyOut;
    uint256 maxCostUsdc;
}
```

**Properties**

| Name | Type | Description |
| ---- | ---- | ----------- |
| sellIndex | `uint256` | Asset to reduce, or IDLE_INDEX (spend idle USDC). |
| buyIndex | `uint256` | Asset to grow, or IDLE_INDEX (keep the sell proceeds idle).<br/>`sellIndex != buyIndex`, and not both IDLE_INDEX. |
| notionalUsdc | `uint256` | USDC notional of the step at TWAP. Lending sell: USDC withdrawn. Basket<br/>sell: the fund sells `assetTokenValue(sellIndex, notionalUsdc)` tokens<br/>(capped at its balance). Idle sell: USDC spent on the buy leg. |
| minSellUsdcOut | `uint256` | Floor on USDC received from the sell leg (§5.3 step 5,<br/>`TWAP quote × (1 − maxStepSlippageBps[sell])`). 0 when sell is idle. |
| minBuyOut | `uint256` | Floor on tokens received by a Basket buy leg for a spend of exactly<br/>`notionalUsdc` (`assetTokenValue(buy, notional) × (1 − slippage)`). If the<br/>sell leg returned less USDC than `notionalUsdc`, the fund spends what it got<br/>and scales this floor by `spend / notionalUsdc`. Ignored for Lending or<br/>idle buys. |
| maxCostUsdc | `uint256` | Per-step cost cap (`notionalUsdc × maxStepCostBps / 10 000`, RB-4). The fund<br/>reverts `StepCostExceeded` if `navBefore − navAfter` exceeds it. |
