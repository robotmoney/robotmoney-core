# AuctionStepExecutor

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/d51a8ed56dc72ae8662acc53f88fb090d86e44cb/contracts/test/prototype/baseline/src/AuctionStepExecutor.sol)

**Inherits:** [IBasketSwapAdapter](/contracts/interfaces/interface.IBasketSwapAdapter), ReentrancyGuard

**Title:** AuctionStepExecutor

Phase 3c fallback for G4. It is the basket assets' `IBasketSwapAdapter`. It forwards TWAP reads
to the pool adapter, so NAV and ORA-4 are unchanged. Inside `fill()` it prices each basket leg as a
Dutch auction against the TWAP and settles with the filler. Elsewhere it passes swaps through.
It holds no funds between calls. See the model note at the top of this file.

<a id="open"></a>

### open

Start the clock for the next step. Anyone. Takes no input (RB-2). Reverts unless the
Rebalancer would trade now (so the cooldown and ORA-4 hold first, RB-5), or while one is live.

```solidity
function open() external nonReentrant;
```

<a id="fill"></a>

### fill

Fill the live auction: run one `Rebalancer.step()` with the caller as the solver of every basket
leg. Takes no input (RB-2). Reverts unless the step executed, so a fill never records a skip or
a backoff. Returns the seconds since the open.

```solidity
function fill() external nonReentrant returns (uint256 elapsed);
```

| Name | Type | Description |
| ---- | ---- | ----------- |
| elapsed | `uint256` |  |

<a id="swap-address-address-uint24-uint256-uint256-address-uint256"></a>

### swap

Execute a single-hop swap.

<i>

A leg of a live fill when the fund calls: TWAP-priced Dutch auction, settled with the filler.
Any other call passes through to `INNER` with the same arguments.

</i>

```solidity
function swap(
        address tokenIn,
        address tokenOut,
        uint24 fee,
        uint256 amountIn,
        uint256 minAmountOut,
        address recipient,
        uint256 deadline
    ) external returns (uint256 amountOut);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| tokenIn | `address` | Address of the token to sell. |
| tokenOut | `address` | Address of the token to buy. |
| fee | `uint24` | Venue-specific fee parameter (fee tier for Uniswap V3,<br/>ignored for Aerodrome which derives fee from pool config). |
| amountIn | `uint256` | Exact amount of `tokenIn` to sell. |
| minAmountOut | `uint256` | Minimum amount of `tokenOut` required; reverts if not met. |
| recipient | `address` | Recipient of `tokenOut`. |
| deadline | `uint256` | Unix timestamp after which the swap must revert. Chosen<br/>by the caller — adapters must not substitute<br/>`block.timestamp` (audit 2026-06-09, L-5). Callers that<br/>execute synchronously within their own transaction (e.g.<br/>BasketVault) may pass `block.timestamp`. |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| amountOut | `uint256` | Actual amount of `tokenOut` received. |

<a id="twapprice-address-address-address-uint256-uint32"></a>

### twapPrice

Compute a TWAP-based price quote: how many `quoteToken` for `baseAmount`
of `baseToken`, reading the oracle from `pool` over `window` seconds.

```solidity
function twapPrice(
        address pool,
        address baseToken,
        address quoteToken,
        uint256 baseAmount,
        uint32 window
    ) external view returns (uint256);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| pool | `address` | Venue-specific pool address pairing `baseToken` with `quoteToken`. |
| baseToken | `address` | Token whose amount is the input to the quote. |
| quoteToken | `address` | Token whose amount is the output of the quote. |
| baseAmount | `uint256` | Amount of `baseToken` to price. |
| window | `uint32` | TWAP lookback window in seconds. |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| &lt;none&gt; | `uint256` | Estimated amount of `quoteToken` for `baseAmount` of `baseToken`. |
