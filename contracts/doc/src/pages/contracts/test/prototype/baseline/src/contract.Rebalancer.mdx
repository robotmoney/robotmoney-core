**Title:** Rebalancer

Step selection for the one vault (§5). It holds no funds, grants no token approvals and
never receives tokens by design: it reads the fund, derives one `StepOrder` purely from
chain state, and calls `fund.executeStep`, which does all custody, swaps, NAV
measurement, the RB-7 guard, the per-step cost cap and the budget halt (RB-3, RB-4).

Authority:
- `step()`: KEEPER_ROLE always; anyone once `keeperGrace` has passed with no step on an
Open plan (§5.4). The caller chooses only WHEN (RB-2).
- Parameters (§5.6): ADMIN_ROLE (the timelock).
On the fund this contract holds REBALANCER_ROLE (`executeStep`, `concludePlan`).

Runtime hardening beyond the pinned interface (prototype choices, see NatSpec below):
- The cooldown is `max(stepInterval, fund.maxTwapWindow())`, so an asset added later
with a longer TWAP window can never make the cooldown shorter than a window (§5.3.1).
- Each leg's slippage floor is clamped to `fund.maxSlippageBps()` at run time, so a
later lowering of the fund ceiling is honoured without re-setting every asset.
- Per-asset backoff: when `executeStep` reverts, both non-idle legs are excluded from
leg picking for one cooldown, so a frozen venue stalls only its own asset while the
rest of the plan keeps converging (§5.8 "A venue freezes").
- Gas starvation: `executeStep` is only called with at least `STEP_GAS_FLOOR` gas left
(else `StepGasStarved`), and a revert that left this frame with under 1/63 of the gas it
forwarded is re-thrown, so a permissionless caller cannot force a fake `StepFailed` and a
backoff by sending too little gas.

Runs behind its own ERC-1967 proxy (`GovernedUUPS`). `fund` is set once at initialize.

## Constants

### ADMIN_ROLE

Sets step parameters and administers KEEPER_ROLE. Held by the timelock.

```solidity
bytes32 public constant ADMIN_ROLE = Roles.ADMIN_ROLE;
```

### KEEPER_ROLE

May call `step()` before `keeperGrace` has passed (§5.4).

```solidity
bytes32 public constant KEEPER_ROLE = Roles.KEEPER_ROLE;
```

### STEP_GAS_FLOOR

Gas that must remain when `step()` calls `fund.executeStep` (RB-2, §5.8 row 5). A measured
worst-case step (two swaps, three TWAP NAV passes over six assets, nested 63/64 forwarding)
stays well under it, so with this much gas no frame inside the step can run out. A caller
that sends less gets `StepGasStarved`: nothing is recorded and no asset backs off. Without
the floor, an out-of-gas inside a nested frame (library, adapter, router, pool) hands every
parent its retained 1/64 back, slips past the `gasBefore / 63` check, and a permissionless
caller could book a fake `StepFailed` and choose which assets get masked.

```solidity
uint256 public constant STEP_GAS_FLOOR = 4_000_000;
```

### step

Run at most one step. Takes no input (RB-2): the caller chooses only WHEN.
Access (§5.4): KEEPER_ROLE always; anyone once
`now ≥ max(fund.lastStepAt(), plan.startTime) + keeperGrace` while the plan is Open;
otherwise reverts `NotKeeperBeforeGrace`. Every other non-execution RETURNS
(does not revert) and emits `RebalanceStepSkipped`.

Order (§5.3):

0. Plan not Open → skip `PlanNotOpen`.

If `now > plan.endTime + maxOverrun` → `fund.concludePlan(Expired)`, return

`(false, Concluded)` (no skip event; the fund's PlanStatusChanged records it).

1. Cooldown: `now &lt; fund.lastStepAt() + effectiveStepInterval()` → skip `Cooldown`.

2. If `now ≥ endTime` and

`PlanMath.withinTolerance(values, idle, nav, endBps, toleranceBps)` →

`fund.concludePlan(Converged)`, return `(false, Concluded)`.

3. Market check: build the eligible mask = active ∧ maxStepUsdc > 0 ∧ not backed

off (`assetBackoffUntil(i) &lt; now`, inclusive end) ∧ `fund.marketCheck(i).ok`. An asset failing

ORA-4 (or an excluded Lending asset) is masked out (RB-5: it is never traded).

4. Pick legs: `PlanMath.pickLegs` over `fund.portfolioValues()` and the plan's

start/end/startIdle at `now`. No over or no under → skip `MarketDeviation`

(detail = first ORA-4 failer) when an asset was masked by ORA-4, else

`Cooldown` (detail = longest backoff left) when one was backed off, else

`NothingToTrade`.

5. Size: `notional = min(over, under, maxStepUsdc[sell], maxStepUsdc[buy])` (idle

legs uncapped). `notional &lt; minStepUsdc` → skip `BelowMinStep`.

6. Floors from TWAP, never spot (each slippage clamped to `fund.maxSlippageBps()`):

Basket sell: `minSellUsdcOut = assetUsdcValue(sell, assetTokenValue(sell, notional))

× (1 − maxStepSlippageBps[sell])`;

Lending sell: `notional × (1 − maxStepSlippageBps[sell])`; idle sell: 0.

Basket buy: `minBuyOut = assetTokenValue(buy, notional) × (1 − maxStepSlippageBps[buy])`;

otherwise 0.

`maxCostUsdc = notional × maxStepCostBps / 10 000`.

7. `try fund.executeStep(order)`; on revert → both non-idle legs back off for one

effective cooldown (`AssetBackoff`) and skip `StepFailed` (detail = selector);

a gas-starved revert re-throws `StepGasStarved`.

Cost cap and budget halt are enforced inside `executeStep` (RB-4).

8. Emit `RebalanceStep` with the legs' path targets at `now`.

<i>

Implements §5.3 steps 1 to 9 in order, plus the §5.5 Converged and Expired transitions.
Takes no input (RB-2). Skips return and emit `RebalanceStepSkipped`; only the access
check (`NotKeeperBeforeGrace`) and gas starvation (`StepGasStarved`) revert.
A concluded plan (Converged or Expired) returns `(false, Concluded)` with the fund's
`PlanStatusChanged` as its only event.

</i>


### previewPlan

Preview a plan for a proposed per-asset target vector at current TWAP. `assets`
names each active asset by its fund asset address (`PlanMath.assetId`: `token` for
Basket, `adapter` for Lending). `bps` is parallel. Per asset (index-aligned to the
fund's list): current weight, the target, turnover `|target − current| × NAV /
10 000`, and estimated cost `turnover × fund.poolFeeBps(i) / 10 000`. Reverts on a
refused vector with the fund's §4.1 errors (RB-9).

<i>

Per asset at current TWAP: `turnover = |target − current| × NAV / 10 000` and
`estCost = turnover × fund.poolFeeBps(i) / 10 000` (0 for Lending). PROTOTYPE ESTIMATE:
pool fee only. It ignores price impact and the slippage allowance, so it is a lower
bound; the realized cost is bounded above by `maxStepCostBps` per step and by
`costBudgetBps` per plan. Reverts on a refused vector with the same `PlanMath.assetTargets`
errors the fund would raise at plan open (§4.1, RB-9), including `TargetExceedsCap`.

</i>

```solidity
function previewPlan(address[] calldata assets, uint256[] calldata bps)
        external
        view
        returns (PlanPreviewRow[] memory rows, uint256 totalTurnover, uint256 totalEstCost);
```

**Parameters**
