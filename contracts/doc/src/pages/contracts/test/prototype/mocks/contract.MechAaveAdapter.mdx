# MechAaveAdapter

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/d51a8ed56dc72ae8662acc53f88fb090d86e44cb/contracts/test/prototype/mocks/MechAaveAdapter.sol)

**Inherits:** [MechReentry](/contracts/test/prototype/mocks/abstract.MechReentry), [ILendingRateAdapter](/contracts/test/prototype/src/interfaces/interface.ILendingRateAdapter)

**Title:** MechAaveAdapter

A lending venue for `FlowQueue.t.sol` that `vm.etch` places over the harness's Aave V3 rate adapter (whose
code keeps no storage). It sits at the same address, so the fund's real aUSDC position on the real Aave
pool stays its own. The test allowlists this code hash through the timelock first, so the asset stays
counted (ADP-2). Modes:
- `HONEST`: supply and withdraw as the production `AaveV3Adapter`, with the venue rate of the copy.
- `ROUND_AGAINST`: the venue rounds against the fund by `param` units on both sides, in its own books:
a supply of `a` raises the position it reports (`totalAssets`) by exactly `a - param` (whatever Aave's
own rounding of up to one unit did, the mock's `haircut` makes the total exactly `param`), and a
withdrawal of `a` pays `a - param`. Proposal §5.9.3 check 10 says one or two units must never fail the
proportion check. (Aave refuses a top-up supply that scales to zero, so the shortfall is booked in the
reported position rather than by supplying less.)
- `SHORT_PAY`: a withdrawal of `a` takes `a` out of the position but pays the fund `a × (1 − param / 10 000)`
and keeps the rest: a venue that pays short without reverting.
Any mode also runs the re-entry probe (`MechReentry`) while armed. USDC a mode keeps stays here.

<a id="deploy-uint256"></a>

### deploy

Receive `amount` USDC from the vault and deploy it into the underlying protocol.

<i>

The in-tree lending adapters (Aave, Morpho, Compound) hand `amount` straight back to
the vault, without reverting, when their venue refuses the supply (security round 2):
a reserve at its supply cap, a frozen reserve, MetaMorpho `AllCapsReached`, a Comet
supply-only pause. A venue that refuses withdrawals too (Aave reserve paused or
inactive, Comet withdraw pause) reverts `VenueWithdrawalsClosed` instead (security
round 3, `IVenueHealthAdapter`). The vault measures what the adapter kept by its own
USDC balance, never by a return value, and leaves the rest idle
(`RobotMoneyVaultOps._allocate`).

</i>

```solidity
function deploy(uint256 amount) external onlyVault;
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| amount | `uint256` | Amount of USDC (6-decimal units) to deploy into the protocol. |

<a id="harvestrewards"></a>

### harvestRewards

Claim any underlying-protocol reward tokens and forward them as
USDC to the owning vault (custody invariant INV-2 — no emissions
stranded on the adapter or router). Permissionless: anyone may
trigger the harvest; the destination is always the vault, never a
caller-supplied address (INV-1).

<i>

Adapters that have no on-chain claimable rewards (e.g. Aave
interest accrues automatically in the aToken balance) implement
this as a no-op. Adapters with discrete reward tokens claim them
here, swap to USDC, and credit the vault. This function MUST NOT
revert when there are no rewards to claim.

</i>

```solidity
function harvestRewards() external;
```
