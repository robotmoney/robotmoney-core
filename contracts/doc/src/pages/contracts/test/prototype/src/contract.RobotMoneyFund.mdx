**Inherits:** ERC4626Upgradeable, [AdminFloorAccessControlCounter](/contracts/lib/abstract.AdminFloorAccessControlCounter), ReentrancyGuardUpgradeable, [GovernedUUPS](/contracts/lib/abstract.GovernedUUPS), [IRobotMoneyFund](/contracts/test/prototype/src/interfaces/interface.IRobotMoneyFund)

**Title:** RobotMoneyFund

The one vault (§4): an ERC-4626 over USDC, share `rmFUND`, behind `GovernedUUPS` (ADR-0014). It holds
a flat list of Lending adapters and Basket tokens, one persistent target weight per asset, and one
rebalance plan at a time. No sleeve or category is stored or read (§4.1, RB-9). It is the union of
`RobotMoneyVault` (cap allocator, ADP-2 exclusion, `ExclusionLedger`) and `BasketVault` (TWAP NAV,
ORA-4, realized-delta mint, proportional sell, `redeemInKind`, emergency unwind), plus the plan state
and `executeStep`.

Authority (RB-1, RB-3):
- GOVERNANCE_ROLE (RebalanceGovernance): `setTargetAndOpenPlan`.
- REBALANCER_ROLE (Rebalancer): `executeStep`, `concludePlan`.
Both are self-administered and granted exactly once by `bindRebalanceRoles`, so no ADMIN_ROLE
holder can hand either to another address (the router's WEIGHT_SETTER_ROLE model).
- EMERGENCY_ROLE (hot key): `pauseRebalance`, `pauseDeposits`, `shutdown`, `emergencyUnwind`.
- ADMIN_ROLE (timelock): assets, caps, fees, guards, `resumePlan`, `extendBudget`, `closePlan`,
`unpauseDeposits`, `restore`, and every role grant. ADMIN carries no upgrade power: only
`upgradeTimelock()` upgrades or freezes the proxy.
- `redeem` and `redeemInKind` are never gated by plan state, pause or shutdown (RB-6).

Size (§6.1, G1): value-moving and validation logic lives in the delegatecall-linked
`FundValuationLib`, `FundFlowsLib`, `FundAdminLib` and (step 3d) `FundPositionLib`, which in turn link the existing
`TwapTickMath`, `BasketSwaps`, `BasketAssetConfigGuard` and `RobotMoneyVaultOps` (ledger creation).
The fund keeps ERC-4626 accounting, roles, plan transitions and lifecycle flags.

Custody (INV-1): no function sends a protocol asset to a caller-supplied address except the
ERC-4626 `receiver` of the caller's own (or allowance-approved) redemption. Swaps pay the fund; USDC
leaves only to an allowlisted adapter, the fixed exit-fee recipient, or the exclusion ledger.

### redeemInKind

Oracle-free, swap-free exit of last resort (§4.4): pro-rata idle and Lending USDC as one leg,
plus each active Basket token, each net of the exit fee. Never gated (RB-6). Step 3d: asserts the

`takeReturn`); then `caller == owner`, so no allowance is spent, and claims are keyed to `receiver`.

<a id="mintinkind-uint256-uint256-uint256"></a>

### mintInKind

FLOW_ROLE only (E3). Buy the pro-rata slice for `sharesOut` new shares and mint them to the caller.
For every active asset and idle USDC, on held amounts (`heldBalances`): the fund adds
`ceil(held × sharesOut / supply)` (idle: kept from the USDC pulled; Lending: supplied, plus
`LENDING_ROUNDING_UNITS`; Basket: an exact-output swap whose input is at most `maxUsdcPerLeg[i]`).
Then it mints exactly `sharesOut` and asserts the proportion check (check 10, `ProportionViolated`).
The caller's USDC falls by exactly `usdcSpent` (≤ `maxUsdc`, else `MintInKindOverMax`); unused USDC is
never taken. A venue that refuses a supply reverts the call. Reverts `NotSeeded` at zero supply,
`LegLimitsLength`, `FlowLegLimit`.

<i>

Body in `FundFlowsLib.mintInKind`, which buys the slice and asserts check 10 against
`supply + sharesOut`; the mint here moves no asset, so the check still holds after it.

</i>

```solidity
function mintInKind(uint256 sharesOut, uint256 maxUsdc, uint256[] calldata maxUsdcPerLeg)
        external
        onlyRole(FLOW_ROLE)
        nonReentrant
        returns (uint256 usdcSpent);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| sharesOut | `uint256` | Shares to mint, computed by the caller and rounded DOWN. |
| maxUsdc | `uint256` | The most USDC the caller lets the fund take (approved to the fund). |
| maxUsdcPerLeg | `uint256[]` | Per asset index (length `assetCount()`): the most USDC the purchase of that Basket<br/>asset may spend (check 9). Ignored for Lending and inactive assets. |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| usdcSpent | `uint256` | USDC taken from the caller. |

<a id="setinkindallowance-uint16-uint128-uint32"></a>

### setInKindAllowance

ADMIN_ROLE. Set the in-kind allowance: per period of `period` seconds, in-kind exits take lending USDC
up to `max(bps × lending holdings / 10 000, floorUsdc)` (E20). `bps ≤ 10 000`, `floorUsdc ≤
MAX_IN_KIND_FLOOR_USDC`, `period` in [MIN_IN_KIND_PERIOD, MAX_IN_KIND_PERIOD] (`InvalidParam`).

<a id="executestep-steporder"></a>

### executeStep

Execute one step's legs (§5.3 steps 5-8). REBALANCER_ROLE only. `nonReentrant`.
Reverts unless the current plan is Open. Order of operations:
1. Validate indices (`InvalidAssetIndex`; sell != buy; not both idle; active).
2. ORA-4 on every Basket leg (`NavMarketDeviationExceeded`, RB-5 defence in depth).
3. Value all holdings at TWAP → `navBefore`. RB-7 guard: the sell leg must be over its
`pathTarget(now)` value by ≥ notional, and the buy leg (if not idle) under it by
≥ notional, else `StepExceedsPath`.
4. Sell leg → USDC: Lending `withdraw(notional)` measured by balance delta; Basket
sells `min(balance, assetTokenValue(sell, notional))` tokens through its swap
adapter with recipient = fund; idle uses `notional` of idle USDC
(`InsufficientIdle`). Require received ≥ `minSellUsdcOut` (`StepBelowMinOut`).
5. Buy leg ← spend = min(received, notional): Lending `deploy(spend)` (USDC the
adapter hands back stays idle); Basket swap with floor `minBuyOut × spend /
notional`, recipient = fund (`StepBelowMinOut`); idle keeps it.
6. `navAfter` at TWAP; cost = max(navBefore − navAfter, 0); revert
`StepCostExceeded` if cost > `maxCostUsdc` (RB-4).
7. plan.costSpent += cost; plan.stepCount += 1; lastStepAt = now. If
costSpent > costBudget: status → Halted (`PlanStatusChanged`).
8. Emit `StepExecuted`.
Every swap recipient is the fund and every USDC destination is an allowlisted
adapter or swap adapter (RB-3, INV-1).

```solidity
function executeStep(StepOrder calldata order)
        external
        onlyRole(REBALANCER_ROLE)
        nonReentrant
        returns (StepResult memory);
```

<a id="emergencyunwind"></a>

### emergencyUnwind

Pause deposits, move every holding to idle USDC (`FundFlowsLib.emergencyUnwind`: Lending drained
tolerant of failure, excluded adapters drained into their exclusion record, Basket sold under the
TWAP floor), and pause an Open or Halted plan so the Rebalancer stops (it would otherwise buy
back, including after a queued `extendBudget` lands).

<i>

Differs from BasketVault: there is no configured per-token floor or override path. A Basket leg
whose TWAP read fails is skipped and stays held; holders still exit it through `redeemInKind`.

</i>

```solidity
function emergencyUnwind() external onlyRole(EMERGENCY_ROLE) nonReentrant;
```

<a id="sweepforeigntoken-address"></a>

### sweepForeignToken

Permissionless: send a non-protected token's whole balance to the fixed quarantine address
(INV-1/INV-2; no caller-chosen destination). Protected (`ProtectedToken`): USDC, the share token,
every asset token (active or not), and every Lending adapter address (an adapter that is itself
a share token).

```solidity
function sweepForeignToken(address token) external nonReentrant;
```

| Name | Type | Description |
| ---- | ---- | ----------- |
| token | `address` |  |
