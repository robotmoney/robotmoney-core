# RouterGovernanceSafeTimelockTest

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/cb1d9cc5d144b8c5c8b47688dd34b616792f0d5e/contracts/test/RouterGovernance.t.sol)

**Inherits:** [RouterGovernanceFixture](/contracts/test/abstract.RouterGovernanceFixture)

The production route, with no vm.prank on any governed path: two of
three owners sign, the real SafeL2 proxy runs `execTransaction`, the
Safe schedules on the timelock, the delay passes, the Safe executes,
the timelock calls `applyReceipt`, and the weight setter releases the
receipt and sets the router weights in that one transaction.

### test_applyReceipt_setsWeightsInOneCall

The acceptance test of issue #1698: one scheduled call, executed
through the real Safe and timelock, leaves `isReleased` true and

<a id="test_applyreceipt_revertsafterstandalonetimelockrelease"></a>

### test_applyReceipt_revertsAfterStandaloneTimelockRelease

Security round 1 (governance-decisions.md §3.2, §3.7): the timelock's own
`ADMIN_ROLE` on the register (stage 11 grants it, `DeployTimelock.s.sol`) lets the
standalone `release-receipt` govern row release a receipt with no weights. That
receipt can never be applied: a later `applyReceipt` for it, scheduled and waited
out like any other, reverts `ReceiptAlreadyReleased` at execute and no weight
lands. Pins that "released" does not mean "applied"; the committee records a new
receipt instead.

```solidity
function test_applyReceipt_revertsAfterStandaloneTimelockRelease() public;
```
