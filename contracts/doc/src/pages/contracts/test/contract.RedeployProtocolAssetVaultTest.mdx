# RedeployProtocolAssetVaultTest

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/cb1d9cc5d144b8c5c8b47688dd34b616792f0d5e/contracts/test/RedeployProtocolAssetVault.t.sol)

**Inherits:** [BasketDeployFixture](/contracts/test/helpers/abstract.BasketDeployFixture)

Single-vault redeploy of rmPROTO into a live deployment (issue 1796).
The deployment state is the Deploy 2 shape: registry and router governed by a timelock, four router-eligible vaults,
the default split 8550 / 525 / 575 / 350. The new vault comes from the redeploy script, unlinked: the registry link is the
timelock's first call in the govern batch (core S5: no vault deploy script links the registry). The govern row's batch is
replayed call by call from the timelock, so the order of retire against migrateEligibility is checked on the real contracts.

### test_batch_linksTheRegistryFirstSoTheRegistryDrivesTheNewVault

<i>

The link lands first in the batch, as the timelock (ADMIN_ROLE on the new vault). After the batch the registry is the one
address that drives the vault's deposit-halt leg, so a later status change through the registry reaches the vault.

</i>

```solidity
function test_batch_linksTheRegistryFirstSoTheRegistryDrivesTheNewVault() public;
```

<a id="test_batch_withoutthelinktheregistrycannotdrivethenewvault"></a>

### test_batch_withoutTheLinkTheRegistryCannotDriveTheNewVault

<i>

Without the link the registry's status setter reverts in the vault's `OnlyRegistry` guard: a batch that forgot the link
would leave a vault the registry cannot retire, which is why the link is in the batch and not optional.

</i>

