# IGateway

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/77c18cc501b58598887747e7c5881b622e1b4fe3/contracts/gateway/interfaces/IGateway.sol)

**Title:** IGateway

Minimal interface stub for the RobotMoney deposit gateway.

<i>

Per the MVP plan (`Plan tracking issue #109` §2.2), the gateway
exposes one state-mutating entrypoint for agents (`depositTo`), an owner-gated
agent lifecycle surface
(`commitAuthorization`/`revealAuthorization`,
`setPolicy`, `revokeAgent`), and a
deposit-pause asymmetry (DEPOSIT_PAUSER pauses deposits, ADMIN
resumes them). A pause stops new deposits. The gateway has no
withdrawal path (owner decision 2026-10-19).

</i>

Authority model (issues #269, #1476, ACL-9). Registration records
`msg.sender` as the agent's owner, only through `commitAuthorization` +
`revealAuthorization`. The owner never changes within a registration.
Only the owner can update the policy. The owner or the agent can revoke.
No role can grant, revoke or renounce `AGENT_ROLE` through the public
role methods. `ADMIN_ROLE` grants no authority over any agent.

Policy rule. Every call that writes a policy applies the same validator,
and every caller must name itself as `shareReceiver`.

## Functions

<a id="depositto-bytes32-uint256-uint64-bytes32-address-uint256"></a>

### depositTo

Pull `amount` USDC from caller, deposit it into `destination`, and
deliver the resulting shares to the agent's `shareReceiver` (the owner).
This is the gateway's only agent action.

<i>

Restricted to `AGENT_ROLE`. Reverts `DepositsArePaused` while deposits are
paused. `destination` must appear in the agent's non-empty
`allowedDestinations`; the gateway pins no vault, has no registry lookup, and
never accepts the Portfolio Router as a target. An empty list authorizes nothing.

</i>

```solidity
function depositTo(
        bytes32 orderId,
        uint256 amount,
        uint64 deadline,
        bytes32 idempotencyKey,
        address destination,
        uint256[] calldata minSharesPerLeg
    ) external returns (bytes32 paymentId);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| orderId | `bytes32` | Caller-supplied order identifier (echoed in event). |
| amount | `uint256` | Gross USDC amount, in 6-decimal base units. |
| deadline | `uint64` | Hard expiry; must be `&lt;= block.timestamp + 600`. |
| idempotencyKey | `bytes32` | Caller-side dedup salt mixed into `paymentId`. |
| destination | `address` | ERC-4626 vault named in the policy. |
| minSharesPerLeg | `uint256[]` | Bound into `paymentId` only. Pass an empty array. |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| paymentId | `bytes32` |       keccak256(abi.encode(OP_DEPOSIT_TO=3, chainId, gateway, agent,<br/>orderId, amount, idempotencyKey, destination, minSharesPerLeg)). |

<a id="commitauthorization-bytes32"></a>

### commitAuthorization

Phase-1 of the two-phase commit/reveal agent authorization.
Submit `commitHash = keccak256(abi.encode(agent, msg.sender, salt))`
to reserve the agent address. Must wait at least one block
before revealing. The commitment expires after
`COMMIT_EXPIRY_BLOCKS` blocks.

<i>

Permissionless. Any EOA may commit. The hash binds the agent
address, the caller identity, and a caller-chosen salt so that
a mempool observer cannot front-run the reveal with a different
depositor address.
An agent address also uses this to consent to an owner (core 1791):
from its own key it submits
`keccak256(abi.encode(owner, keccak256(callData)))`, where `callData` is
the full `revealAuthorization(agent, salt, policy)` calldata `owner` will
send. That reveal then consumes it, so the consent covers one agent, one
policy and one salt. Without the consent the reveal reverts
`OwnerConsentMissing`, so nobody can take an address that never agreed.

</i>

```solidity
function commitAuthorization(bytes32 commitHash) external;
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| commitHash | `bytes32` | `keccak256(abi.encode(agent, msg.sender, salt))`, or the consent hash above. |

<a id="revealauthorization-address-bytes32-agentpolicy"></a>

### revealAuthorization

Phase-2 of the two-phase commit/reveal agent authorization.
Reveal `agent` and `salt` to validate the prior commitment and
authorize the agent with the supplied policy. Reverts if no
prior commitment matches, if the commitment has expired, if
`msg.sender` is not the original committer, or if the hash
does not match. For an `agent` other than the caller it also
reverts `OwnerConsentMissing` unless the agent consented to this
caller and this exact call through `commitAuthorization`.

<i>

Must be called at least one block after `commitAuthorization`.
The policy is checked by the same validator as `setPolicy`:
every caller must name itself as
`shareReceiver` (`ShareReceiverNotAuthorized`).

</i>

```solidity
function revealAuthorization(address agent, bytes32 salt, AgentPolicy calldata p) external;
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| agent | `address` | The agent address to authorize (must not already be owned). |
| salt | `bytes32` | The caller-chosen salt used when building `commitHash`. |
| p | `AgentPolicy` | Initial policy parameters. |

<a id="setpolicy-address-agentpolicy"></a>

### setPolicy

Update the policy for an agent the caller already owns.
Reverts `NotAgentOwner` if `msg.sender` is not the recorded
owner of `agent`. The new policy passes the same validator as
registration: the caller must name itself as `shareReceiver`
(`ShareReceiverNotAuthorized`). Reverts `AgentPolicyExpired`
once the stored `validUntil` has passed, so an expired
registration cannot be revived. Emits `AgentAuthorized`.

```solidity
function setPolicy(address agent, AgentPolicy calldata p) external;
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| agent | `address` | The agent address whose policy to update. |
| p | `AgentPolicy` | New policy parameters. |

<a id="revokeagent-address"></a>

### revokeAgent

End an agent registration. The recorded owner or the agent
itself (self-revoke) can call it (`NotAgentOwner` otherwise).
Clears policy, role, owner record and the agent's rolling
deposit window. Emits `AgentRevoked(agent, owner)`.

```solidity
function revokeAgent(address agent) external;
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| agent | `address` | The agent address whose policy and role are revoked. |

<a id="unpausedeposits"></a>

### unpauseDeposits

Resume deposits. Restricted to `ADMIN_ROLE` (asymmetric).
`ADMIN_ROLE` is retained as the counterweight to
`pauseDeposits`; it has no authority over the
lifecycle of an agent it does not own.

```solidity
function unpauseDeposits() external;
```

<a id="effectivedepositwindowgross-address"></a>

### effectiveDepositWindowGross

Cumulative USDC the agent has deposited in the current rolling
deposit window. Returns zero when the agent has either never
deposited or the last anchor lies more than `WINDOW_SECONDS` in
the past. Use this — not the deprecated `agentWindowGross`
mapping — to project whether the next deposit would breach
`maxPerWindow` (issue #497).

```solidity
function effectiveDepositWindowGross(address agent) external view returns (uint256);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| agent | `address` | The agent address to look up. |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| &lt;none&gt; | `uint256` | The agent's cumulative rolling-window deposit gross. |

## Events

### CommitSubmitted

Emitted when a depositor submits a commitment hash for a
future `revealAuthorization` call.

```solidity
event CommitSubmitted(
        address indexed committer, bytes32 indexed commitHash, uint64 blockNumber
    );
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| committer | `address` | EOA that submitted the commitment (`msg.sender`). |
| commitHash | `bytes32` | `keccak256(abi.encode(agent, committer, salt))`. |
| blockNumber | `uint64` | Block number at which the commitment was recorded. |

### CommitRevealed

Emitted when a depositor successfully reveals a commitment and
the agent is authorized.

```solidity
event CommitRevealed(
        address indexed committer, bytes32 indexed commitHash, address indexed agent
    );
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| committer | `address` | EOA that revealed (must equal the original committer). |
| commitHash | `bytes32` | The commitment hash that was revealed and cleared. |
| agent | `address` | Agent address that was authorized. |

### AgentAuthorized

Emitted when an agent's policy is created or updated.

```solidity
event AgentAuthorized(
        address indexed agent,
        address indexed owner,
        uint64 validUntil,
        uint256 maxPerPayment,
        uint256 maxPerWindow,
        address shareReceiver
    );
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| agent | `address` | Agent address whose policy was set. |
| owner | `address` | The agent's recorded owner, which is `msg.sender`<br/>of the `revealAuthorization` or<br/>`setPolicy` call that emitted it. |
| validUntil | `uint64` | Policy expiry timestamp (Unix seconds). |
| maxPerPayment | `uint256` | Maximum USDC per single deposit call. |
| maxPerWindow | `uint256` | Maximum USDC per rolling window. |
| shareReceiver | `address` | Address receiving minted vault shares. |

## Structs

### AgentPolicy

Per-agent policy. Set by the agent's recorded owner via
`revealAuthorization` (first time) or `setPolicy` (subsequent
updates).

```solidity
struct AgentPolicy {
        bool active;
        uint64 validUntil;
        uint256 maxPerPayment;
        uint256 maxPerWindow;
        address shareReceiver;
        address[] allowedDestinations;
        address assetRecipient;
        uint256 maxWithdrawPerPayment;
        uint256 maxWithdrawPerWindow;
        address[] allowedSourceVaults;
    }
```

**Properties**

| Name | Type | Description |
| ---- | ---- | ----------- |
| active | `bool` | Policy is enabled. |
| validUntil | `uint64` | Unix-seconds expiry; deposits revert at/after. |
| maxPerPayment | `uint256` | Maximum gross USDC per single `deposit` call. |
| maxPerWindow | `uint256` | Maximum gross USDC per `WINDOW_SECONDS` window. |
| shareReceiver | `address` | Address that receives minted vault shares. |
| allowedDestinations | `address[]` | Contracts the agent may deposit into (ERC-4626 vaults the<br/>owner selected). Must be non-empty with no zero entry.<br/>`depositTo` requires the destination to appear here.<br/>The router is never a destination. |
| assetRecipient | `address` | RETIRED. Must be zero. |
| maxWithdrawPerPayment | `uint256` | RETIRED. Must be zero. |
| maxWithdrawPerWindow | `uint256` | RETIRED. Must be zero. |
| allowedSourceVaults | `address[]` | RETIRED. Must be empty. |
