# RobotMoneyGateway

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/77c18cc501b58598887747e7c5881b622e1b4fe3/contracts/gateway/RobotMoneyGateway.sol)

**Inherits:** [AccessRoles](/contracts/gateway/abstract.AccessRoles), ReentrancyGuardUpgradeable, [IGateway](/contracts/gateway/interfaces/interface.IGateway), [GovernedUUPS](/contracts/lib/abstract.GovernedUUPS)

**Title:** RobotMoneyGateway

Policy-gated agent deposit into an owner-selected ERC-4626 vault. Pulls USDC
from the agent, enforces per-agent caps and a rolling per-window cap, deposits
into a destination named in the depositor's `allowedDestinations`, and mints
the shares to the policy's share receiver (the owner).

<i>

Canonical: docs/architecture.md §5.2. The gateway pins no vault list and has no
registry lookup: the policy list is the only destination authority, and the
Portfolio Router is never a destination. The agent has no withdrawal path.
Custom errors only; OZ v5 SafeERC20; the gateway never custodies vault shares.
The idempotency hash deliberately excludes `deadline`.

</i>

Runs behind its own ERC-1967 proxy (issue 1808): `initialize` replaces the
constructor, the implementation is locked, and only `upgradeTimelock()` can upgrade
or freeze it (`GovernedUUPS`). No gateway role carries upgrade power. `usdcToken`
is set once at initialization, no setter. `vaultContract`, `routerContract` and the
withdraw window state are retired storage kept only for the proxy layout gate.

## Constants

### DEPOSIT_GAS_FLOOR

<i>

Gas `depositTo` needs at entry. The vault's deposit entry floor is 1_600_000 after
the 63/64 forward, and the gateway spends its policy reads, window and payment-id
writes and the USDC pull before the call.

</i>

```solidity
uint256 internal constant DEPOSIT_GAS_FLOOR = 2_000_000;
```

### WINDOW_SECONDS

Window length in seconds for per-window gross caps. Unix-epoch
aligned: `windowId = block.timestamp / WINDOW_SECONDS`.

```solidity
uint64 public constant WINDOW_SECONDS = 86400;
```

### MAX_DEADLINE_SKEW

Maximum future skew permitted on `deadline` arguments.

```solidity
uint256 public constant MAX_DEADLINE_SKEW = 600;
```

### COMMIT_EXPIRY_BLOCKS

Number of blocks after which an unrevealed commitment expires.
After `commitBlock + COMMIT_EXPIRY_BLOCKS` the commitment can
no longer be revealed and the depositor must re-commit.

```solidity
uint256 public constant COMMIT_EXPIRY_BLOCKS = 256;
```

### OP_DEPOSIT_TO

Op-kind discriminator prepended to the `paymentId` hash. The value 3 is kept
from the deployed release so ids stay stable, and the retired kinds (1, 2, 4)
are never reused.

```solidity
uint8 internal constant OP_DEPOSIT_TO = 3;
```

### MAX_WINDOW_ENTRIES

Hard cap on the number of distinct live ring-buffer entries per
agent per side. Because same-second operations coalesce, the live
count can never exceed the number of distinct seconds in the
rolling window; this constant pins the storage footprint regardless
and makes the bound explicit. `WINDOW_SECONDS` distinct seconds is
the theoretical ceiling, but no real agent approaches it — the cap
exists purely so the worst case is provably O(1) in storage.

```solidity
uint256 public constant MAX_WINDOW_ENTRIES = WINDOW_SECONDS;
```

<a id="commitauthorization-bytes32"></a>

### commitAuthorization

Phase-1 of the two-phase commit/reveal agent authorization.
Submit `commitHash = keccak256(abi.encode(agent, msg.sender, salt))`
to reserve the agent address. Must wait at least one block
before revealing. The commitment expires after
`COMMIT_EXPIRY_BLOCKS` blocks.

<i>

Permissionless. Any EOA may commit. The hash binds the agent
address, the caller identity, and a caller-chosen salt so that
a mempool observer cannot front-run the reveal with a different
depositor address.
An agent address also uses this to consent to an owner (core 1791):
from its own key it submits
`keccak256(abi.encode(owner, keccak256(callData)))`, where `callData` is
the full `revealAuthorization(agent, salt, policy)` calldata `owner` will
send. That reveal then consumes it, so the consent covers one agent, one
policy and one salt. Without the consent the reveal reverts
`OwnerConsentMissing`, so nobody can take an address that never agreed.

</i>

```solidity
function commitAuthorization(bytes32 commitHash) external;
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| commitHash | `bytes32` | `keccak256(abi.encode(agent, msg.sender, salt))`, or the consent hash above. |

<a id="revealauthorization-address-bytes32-agentpolicy"></a>

### revealAuthorization

Phase-2 of the two-phase commit/reveal agent authorization.
Reveal `agent` and `salt` to validate the prior commitment and
authorize the agent with the supplied policy. Reverts if no
prior commitment matches, if the commitment has expired, if
`msg.sender` is not the original committer, or if the hash
does not match. For an `agent` other than the caller it also
reverts `OwnerConsentMissing` unless the agent consented to this
caller and this exact call through `commitAuthorization`.

<i>

Must be called at least one block after `commitAuthorization`.
The policy is checked by the same validator as `setPolicy`:
every caller must name itself as
`shareReceiver` (`ShareReceiverNotAuthorized`).

</i>

```solidity
function revealAuthorization(address agent, bytes32 salt, AgentPolicy calldata p) external;
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| agent | `address` | The agent address to authorize (must not already be owned). |
| salt | `bytes32` | The caller-chosen salt used when building `commitHash`. |
| p | `AgentPolicy` | Initial policy parameters. |

<a id="depositto-bytes32-uint256-uint64-bytes32-address-uint256"></a>

### depositTo

Pull `amount` USDC from caller, deposit it into `destination`, and
deliver the resulting shares to the agent's `shareReceiver` (the owner).
This is the gateway's only agent action.

<i>

The only agent action. Deposits into `destination`, which must appear in the
policy's non-empty `allowedDestinations`. No registry lookup, no pinned vault.

`paymentId` (GW-2) and is not otherwise enforced: the gateway has no router leg.

</i>

```solidity
function depositTo(
        bytes32 orderId,
        uint256 amount,
        uint64 deadline,
        bytes32 idempotencyKey,
        address destination,
        uint256[] calldata minSharesPerLeg
    ) external nonReentrant onlyRole(AGENT_ROLE) returns (bytes32 paymentId);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| orderId | `bytes32` | Caller-supplied order identifier (echoed in event). |
| amount | `uint256` | Gross USDC amount, in 6-decimal base units. |
| deadline | `uint64` | Hard expiry; must be `&lt;= block.timestamp + 600`. |
| idempotencyKey | `bytes32` | Caller-side dedup salt mixed into `paymentId`. |
| destination | `address` | ERC-4626 vault named in the policy. |
| minSharesPerLeg | `uint256[]` | Bound into `paymentId` only. Pass an empty array. |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| paymentId | `bytes32` | keccak256(abi.encode(OP_DEPOSIT_TO=3, chainId, gateway, agent,<br/>orderId, amount, idempotencyKey, destination, minSharesPerLeg)). |


`revealAuthorization` named an `agent` other than the caller, and the

```solidity
error OwnerConsentMissing();
```

### CommitmentNotFound

`revealAuthorization` called but no prior commitment exists for
this commit hash. The depositor must call `commitAuthorization`
first and wait at least one block.

```solidity
error CommitmentNotFound();
```

### CommitmentExpired

`revealAuthorization` called after the commitment has expired
(block.number > commitBlock + COMMIT_EXPIRY_BLOCKS).

```solidity
error CommitmentExpired();
```

### CommitmentOwnerMismatch

Unused since core 1791 (the check was unreachable: the commit hash binds
the caller). Kept so the ABI and its clients do not change.

```solidity
error CommitmentOwnerMismatch();
```

### CommitmentHashMismatch

`revealAuthorization` called but `keccak256(agent, msg.sender, salt)`
does not match the stored commitment hash.

```solidity
error CommitmentHashMismatch();
```

### CommitmentTooRecent

`revealAuthorization` called in the same block as the commitment.
Must wait at least one block before revealing.

```solidity
error CommitmentTooRecent();
```

### ShareReceiverNotAuthorized

A caller named a `shareReceiver` other than itself. Raised by
`revealAuthorization` and `setPolicy`: every policy writer applies
the same rule to every caller, whatever its role (ACL-9).

```solidity
error ShareReceiverNotAuthorized();
```

### InvalidDestination

`depositTo` was called with a destination not in the agent's
`allowedDestinations` list. An empty list authorizes nothing. The policy list is
the only destination authority: the gateway pins no vault and has no registry.

```solidity
error InvalidDestination();
```

### EmptyAllowedDestinations

A policy named no `allowedDestinations`, or named the zero address as one.

```solidity
error EmptyAllowedDestinations();
```

### RetiredPolicyFieldNonZero

A policy set a retired withdraw member (`assetRecipient`, `maxWithdrawPerPayment`,
`maxWithdrawPerWindow`, `allowedSourceVaults`). The gateway has no withdraw path,
so the members must be zero or empty (architecture 5.2).

```solidity
error RetiredPolicyFieldNonZero();
```

### WindowBufferFull

Raised when an agent's live window-entry count would exceed
`MAX_WINDOW_ENTRIES`. Unreachable in practice (same-second
coalescing keeps the live count far below the cap) but guarantees
the ring buffer can never silently overflow its bound.

```solidity
error WindowBufferFull();
```

### LastAdminFloor

Revoking/renouncing the sole holder of an admin tier is forbidden.

```solidity
error LastAdminFloor();
```

### DepositWindow

Per-agent rolling-window deposit accounting (issue #497).
Eliminates the fixed-window boundary burst on the deposit side.
An agent cannot deposit more than `maxPerWindow` in any contiguous
`WINDOW_SECONDS`-wide interval regardless of calendar boundary.

```solidity
struct DepositWindow {
        uint64 windowStart;
        uint256 gross;
    }
```

**Properties**

| Name | Type | Description |
| ---- | ---- | ----------- |
| windowStart | `uint64` | Unix-seconds anchor of the agent's current rolling window.<br/>Zero when the agent has never deposited. |
| gross | `uint256` | Cumulative USDC deposited since `windowStart`. |

### WithdrawWindow

Per-agent rolling-window withdrawal accounting (issue #449).
The withdrawal cap is enforced as a strict rolling window of
length `WINDOW_SECONDS`: at any time `t`, the cumulative shares
redeemed in the half-open interval `(windowStart, t]` may not
exceed `policy.maxWithdrawPerWindow`. `windowStart` is anchored
to the agent's first withdrawal in each rolling window and
advances to `block.timestamp` only after a full `WINDOW_SECONDS`
has elapsed with no further withdrawal — eliminating the
fixed-window boundary burst that allowed ~2× per-window draw
at calendar-aligned window edges.

```solidity
struct WithdrawWindow {
        uint64 windowStart;
        uint256 gross;
    }
```

**Properties**

| Name | Type | Description |
| ---- | ---- | ----------- |
| windowStart | `uint64` | Unix-seconds anchor of the agent's current rolling window.<br/>Zero when the agent has never withdrawn. |
| gross | `uint256` | Cumulative shares redeemed since `windowStart`. |
