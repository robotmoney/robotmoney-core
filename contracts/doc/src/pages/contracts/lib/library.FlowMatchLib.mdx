# FlowMatchLib

[Git Source](https://github.com/robotmoney/robotmoney-core/blob/d26015d044a6162bbd93106a89523fa140073356/contracts/lib/FlowMatchLib.sol)

**Title:** FlowMatchLib

Linked library holding Step 3f's O(1) whole-match booking, running match indexes, lazy per-owner
claim materialization, post-`maxRoll` redemption notice returns, wind-down release, and
index-historical share views for `FundExclusionLedger` (E24, E35, E38, E40, E52).

## Constants

### MATCH_SCALE

<i>

Precision scale for factor ratios (1e30 leaves > 1e12 headroom up to 1e30 shares without rounding collapse).

</i>

```solidity
uint256 internal constant MATCH_SCALE = 1e30;
```

### ACC_SCALE

<i>

Precision scale for cumulative matched USDC per unit normalized redemption basis.

</i>

```solidity
uint256 internal constant ACC_SCALE = 1e36;
```

<a id="ensureinitialized-flowstate"></a>

### ensureInitialized

Ensure the Step 3f match cycle counters are initialized (`>= 1`).

<i>

The wind-down era is NOT touched here: it starts at 0 and only `onShutdown` raises it. A queue upgraded in
place from v0.8 never ran `initialize`, and its requests (old ones, and the first new one, which records its
era before `registerCreated` calls this) carry era 0. Raising the era here orphaned them from every round.

</i>

```solidity
function ensureInitialized(FlowState storage s) public;
```

### _settleDepMatchShares

<i>

Book one participant's floor share of a deposit match record. Each participant syncs a record exactly
once with the normBasis it held at booking (consume paths sync first), so `remainingNormBasis` reaches
zero when the last participant syncs; the floor-rounding leftover then has no owner and moves from held
shares to `dustShares`, keeping the books exact.

</i>

