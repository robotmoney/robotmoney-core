### contracts-core deferred / dropped QA items

Deferred (not ported, would need redesign on dev's governed UUPS system):

- QA `runAuthority` / `TIMELOCK_ADDRESS` authority stage in DeployTimelock (QA DeployTimelock.s.sol:114-172, 185-190, 285-315). Why: dev's timelock-last order with a CREATE2-predicted timelock replaces it. Finding: none.

Why: tied to QA publish-contracts/src/layout-compare.ts, dropped with QA P0-P4. Finding: none.
- QA redeploy flow where the registry link, cap copy and unpause are one govern batch and the script never calls `setRegistry` (QA RedeployProtocolAssetVault.s.sol:7-15, 90-111, E1/E3). Why: dev's final single-vault redeploy (#1797) links the registry in the script after checking the timelock holds ADMIN_ROLE on it, and `check-set-registry-owner.ts` allow-lists it. - QA `_kindConfig()` hook for the three basket kinds (QA AgentTokenVault.sol:86-90 and siblings). Why: dev's per-kind `initialize` calling `__BasketVault_init` is canonical. Finding: none.
- QA `BasketSwapOps` library (QA BasketSwapOps.sol, 467 lines) and `ExclusionLedgerFactory`, `VaultAdapterOps`, `GatewayAuth`, `GatewayWithdrawOps`, `GovernedUpgrade`, `GovernedProxyDeploy`, `DeployUpgradeAuthority`. The QA behaviour inside them (dust skip, sell anchor, ledger, router legs) was ported or already present.
- `DeployLibs.s.sol`: reset to dev (QA's added library/factory references and manifest keys removed). Why: they named deleted QA libraries. Finding: none.
