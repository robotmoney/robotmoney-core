# v0.9.0 in-place upgrade audit of Deploy 4

**Status:** technical record, 2026-11-20. The decision it led to is
[ADR-0020](../adr/ADR-0020-in-place-upgrades-run-a-one-time-migration.md).
The upgrade procedure is `docs/runbooks/contract-qa/releases/v0.9.0-onevault-upgrade.yaml`.

Owner decision, 2026-11-20: fix everything in this release, including the
Rebalancer upgrade in place and the exclusion ledger replacement.

## Scope

The first Twin rehearsal of the v0.9.0 upgrade ran `upgradeToAndCall(impl, "")`
on the fund and the queue: no migration. v0.9.0 was written and tested for fresh
deployments. This audit compares the storage the contracts 0.8.0 build wrote
(commit `fa7c47182`, the live Deploy 4 build) with what the 0.9.0 code reads.

## Storage diff, 0.8.0 to 0.9.0

The top-level `FlowState` and `FundState` structs are append-only. The changes
are inside structs reached from them.

- **`Request`** (queue `requests`). 0.8.0: slot 3 `limit`, slot 4 `closed`.
  0.9.0: slot 3 `closed, exitFeeBps, minHold, maxRoll, createdAt, expiryEpoch`,
  slot 4 `expiresAt, noticeRound, era, enrolled`, slots 5 to 9 new. A legacy
  `limit` reads as six fields. A legacy `closed` reads as `expiresAt = 1`.
- **`Settlement`** (queue `settlements`). 0.8.0: slot 1 `depositBoundPrice`,
  slot 2 `redeemBoundPrice`, slots 3 to 6 `usdcIn, sharesMinted, sharesBurned,
  usdcOut`, slot 7 `frozenUntil, returnAllowed, holdEndsAt`. 0.9.0: slots 1 to 3
  `matchedShares, matchedUsdc, matchSharePrice`, slots 4 to 7 `usdcIn` to
  `usdcOut`, slot 8 `frozenUntil, freezeSetAt, holdEndsAt`. Every member after
  slot 0 moved by one slot.
- **`StepParams`** (Rebalancer `_stepParams`). 0.8.0: `stepInterval,
  keeperGrace, maxOverrun, maxStepCostBps, toleranceBps, minStepUsdc`. 0.9.0
  drops `keeperGrace`. Every later member moved down inside the one slot.
- **`FlowParams`** gains `cancelBuffer, maxPause, matchBandBps` in free bytes of
  its last slot. Nothing moves. The three read 0 after an empty upgrade.
- **`oldestEpoch`** was an epoch number in 0.8.0. In 0.9.0 it is an index into
  `activeEpochs` (`contracts/lib/FlowSettleLib.sol`).
- **Why the layout gate passed.** The layout fixtures listed a namespaced field
  as a flat source line (`mapping(uint256 id => Request) requests;`). The
  members of a struct behind a mapping were never compared.

## Hazards and fixes

Line numbers in the code references are those of the audited tree and are left
out. "Migrations" is commit `588a68598`: `FlowQueue.migrateV090`
(`contracts/lib/FlowMigrateLib.sol`), `RobotMoneyFund.migrateV090`
(`contracts/lib/FundMigrateLib.sol`) and `Rebalancer.migrateV090`
(`contracts/Rebalancer.sol`).

Two more defects came out of the same rehearsal:

- The queue's wind-down era was raised to 1 after the first post-upgrade request
  had recorded era 0. That request was orphaned from every round. Fixed by
  commit `0dff21438`: the era starts at 0 and only a shutdown raises it.
- The layout gate missed all three struct changes. Fixed by commits `895c76d38`
  (merged as `a0f81d7b3`) and `eb749c502`: the gate compares struct members
  against the committed 0.8.0 baseline and requires each declared migration to
  exist.

The release tooling carries the migrations since commit `a2075f3f6`
(`publish-contracts/src/fund-migrations.ts`).

## Migration spec and what the code does

On-chain order: the Rebalancer upgrade with its migration, the fund upgrade with
its migration, the queue upgrade with its migration. All three run before any
settlement.

**Queue**, `FlowQueue.migrateV090(cancelBuffer, maxPause, matchBandBps)`:

1. Require `totalPendingUsdc == 0`, `totalEscrowShares == 0`, an empty
   `activeEpochs` and `windDownEra == 0`.
2. Rewrite every request `1..requestCount` and every settlement
   `1..settlementCount` into the 0.9.0 layout. An entry that is not in the 0.8.0
   layout reverts.
3. For every claim, a deposit claim with `claimed < shares` adds the rest to
   `ownerHeldShares[owner]`. Require the sum to equal `totalHeldShares`.
4. Write the three parameters with their own bounds (fields 18 to 20 of
   `checkFlowParams`). The whole-struct check cannot run yet: the legacy swap
   adapter fails it until the adapter swap of ADR-0019.
5. Set `oldestEpoch = 0` and delete `cursors`.

The Deploy 4 values are `cancelBuffer = 900`, `maxPause = 259200` and
`matchBandBps = 10`.

**Fund**, `RobotMoneyFund.migrateV090(rebalancer)`:

1. Write the five defaults of a fresh fund: `minPoolDepthUsdc = 2,000,000 USDC`,
   `feeMarginBps = 20`, `delistBandBps = 300`, `delistBudgetBps = 300`,
   `maxBasketBps = 10000`.
2. Require the old ledger empty, then create a new `FundExclusionLedger` bound
   to the fund.
3. Require `rebalancer` to hold `REBALANCER_ROLE` and to answer
   `lastBasketStepAt()`, then write `fund.rebalancer`.

The fund had 382 bytes left under EIP-170. The body is in the linked library
`FundMigrateLib`, and the library applies the `reinitializer(2)` gate itself.

**Rebalancer**, `Rebalancer.migrateV090()`: rewrite `_stepParams` from the
0.8.0 slot layout. A slot that does not decode to values inside the hard bounds
reverts `StepParamOutOfBounds`.

## Checked safe

Legacy redemption claims, `withdrawCredit`, sweep, `claimCursor`, the epoch
anchors, the period caps, `lastSettleEpoch`, the lending rates, the levers, the
roles, the lazy cycle initialization, `maxDepositMinHold`, the pause timestamps,
the lending and delisting claim accumulators, and wind-down with the era
starting at 0 (after commit `0dff21438`).

## Unknowns

- Only the Twin at pin 59716257 was read, not Base after the pin.
- `FlowSettleLib` (the second half), `FundFlowsLib` and `FundPositionLib` were
  checked by field search only.
- Hazards 7, 10 and 12 were reasoned from the code, not executed, at audit time.
  The migrations for 7 and 10 are now executed by the upgrade test on synthetic
  state. Hazard 12 is fixed in `FlowCheckLib` (row 12 above). Its test runs on synthetic state: it zeroes the
  recorded value of one asset in the queue's storage, delists that asset, and reads `checkSettle()`
  (`SafetyReview090.t.sol::test_AGY11_delistBeforeFirstRecordedValueDoesNotTripCheck6`). It has not run on
  Deploy 4's real state.
