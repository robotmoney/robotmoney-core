#### 2.2 `migrateV090` One-Time State Migrations (`ADR-0020`)
- **`Rebalancer.migrateV090()` ([Rebalancer.sol#L199](../../../contracts/Rebalancer.sol#L199)):** uses OpenZeppelin `reinitializer(2)`; unpacks `_stepParams` from the `v0.8.0` slot packing without `keeperGrace` and reverts `StepParamOutOfBounds` on invalid values. Zero external calls, enabling it to upgrade first.
- **`RobotMoneyFund.migrateV090(address rebalancer)` ([FundMigrateLib.sol#L56-L112](../../../contracts/lib/FundMigrateLib.sol#L56-L112)):**
  - Enforces `msg.sender == GovernedUpgrade.layout().upgradeTimelock` (`NotUpgradeTimelock`) and manually reads/writes OpenZeppelin's `GovernedUpgrade.INITIALIZABLE_STORAGE` (`initializing || initialized >= 2 -> InvalidInitialization()`, sets `initialized = 2`, emits `Initialized(2)`) inside the DELEGATECALL library to stay below EIP-170's 24 KB limit (saving `191` of the `382` remaining bytes per [ADR-0020#L46](../../adr/ADR-0020-in-place-upgrades-run-a-one-time-migration.md#L46)). Because this reinitializer check is custom library logic rather than OZ's `reinitializer(2)` modifier, it increases audit surface relative to `FlowQueue`/`Rebalancer`, though its slot checks match OZ v5.0.2 `InitializableStorage`.
  - Sets the five Step 3f defaults (`minPoolDepthUsdc = 2_000_000e6`, `feeMarginBps = 20`, `delistBandBps = 300`, `delistBudgetBps = 300`, `maxBasketBps = 10_000`); replaces the old `ExclusionLedger` with a newly deployed `FundExclusionLedger` after verifying `exclusionCount() == 0 && heldUsdc() == 0` (`OldLedgerNotEmpty`); and records `rebalancer` after verifying `REBALANCER_ROLE` + `lastBasketStepAt()` (`NotTheRebalancer` / `RebalancerNotUpgraded`).
  - **Caveat (`ADR-0020#L48`):** does not verify existing pools satisfy `minPoolDepthUsdc` during migration (`setFlowParams` / `Rebalancer` pool checks evaluate them at runtime).
- **`FlowQueue.migrateV090(cancelBuffer_, maxPause_, matchBandBps_)` ([FlowMigrateLib.sol#L22-L253](../../../contracts/lib/FlowMigrateLib.sol#L22-L253)):**
  - Protected by `reinitializer(2)` + `upgradeTimelock`. Requires zero pending USDC, zero escrowed shares, empty `activeEpochs`, and `windDownEra == 0`.
  - Rewrites `Request` (5 -> 10 slots) and `Settlement` (8 -> 9 slots) entries across mappings `1..requestCount` and `1..settlementCount`, failing closed on unexpected layouts (`NotLegacyRequest` / `NotLegacySettlement`), open legacy requests (`LegacyRequestOpen`), live `returnAllowed` freezes (`LegacyReturnAllowed`), or backfill `ownerHeldShares` discrepancies (`HeldSharesMismatch`).
  - **Scalability note ([ADR-0020#L49](../../adr/ADR-0020-in-place-upgrades-run-a-one-time-migration.md#L49)):** unbounded loops over all historical requests, settlements, and claims run in a single timelock tx—safe on Deploy 4 (6 requests, 3 settlements, 5 claims), unsuitable without chunking for high-volume histories.
  - **Known open hazard:** Hazard #12 / **AGY-11** (see [v0.9.0-in-place-upgrade-audit.md](../../technical/v0.9.0-in-place-upgrade-audit.md); must settle once under `v0.9.0` before calling `delistAsset`, currently enforced by operational procedure only).

#### 2.3 Upgrade Runbook & Dual-Hash Adapter Verification (`ADR-0019`, `v0.9.0-onevault-upgrade.yaml`)
- **Adapter Proxy Vetting (`ADR-0019`, [FundAdapterGuard.sol#L20-L45](../../../contracts/lib/FundAdapterGuard.sol#L20-L45)):** `vet()` enforces that any adapter whose `codehash` is flagged in `adapterProxyCodeHash` keeps both its proxy `codehash` in `codeHashAllowed` **and** its `implementation()`'s `codehash` in `codeHashAllowed` (and not marked as a proxy hash). `vet()` runs on admission, swap, and `FundValuationLib` TWAP reads, whereas `StepFeedLib._twap` (for zero-balance assets) and `FlowCheckLib._requireFundedPoolsFixedFee` (`isFixedFeePool`) currently bypass `vet()` (**AGY-09**), and direct non-proxy adapters skip `codeHashAllowed` in `vet()`. `setAssetAdapter` is timelock-gated and permitted while a plan is live (since swap adapters hold zero inter-call custody), while lending adapters remain direct non-proxied deployments.
- **Runbook Predecessor Chain ([v0.9.0-onevault-upgrade.yaml#L35-L42,L804-L892](../../runbooks/contract-qa/releases/v0.9.0-onevault-upgrade.yaml#L804-L892)):** executes four operations chained strictly by TimelockController `predecessor` under `TIMELOCK_MIN_DELAY` (`900s` / 15 minutes on Deploy 4 rehearsal and Twin; `48h` applies in production, while `v0.9.0-onevault-upgrade.yaml:17` is restricted to `onlyFor: ["twin", "rehearsal"]`):
  1. `P2.87` (`rebalancer.upgradeToAndCall(impl, migrateV090())`, no predecessor)
  2. `P2.80` (`fund.upgradeToAndCall(impl, migrateV090(rebalancer))`, predecessor = `P2.87`)
  3. `P2.81` (`queue.upgradeToAndCall(impl, migrateV090(FLOW_CANCEL_BUFFER, FLOW_MAX_PAUSE, FLOW_MATCH_BAND_BPS))`, predecessor = `P2.80`)
  4. `P2.85` (`scheduleBatch` allowing new swap adapter proxy/impl codehashes and switching basket assets via `setAssetAdapter`, predecessor = `P2.81`)
  - **Assessment:** Predecessor chaining prevents cross-version incompatibility during execution; note from [ADR-0020#L51,L57](../../adr/ADR-0020-in-place-upgrades-run-a-one-time-migration.md#L51) that single `eth_call` simulation checks each step in isolation (with state override for the Rebalancer slot) rather than the full 3-step sequence atomically, leaving the Twin fork as the primary real-state multi-step test.
