## Finding GW-GOV-1 — Agent consent can be used long after its commitment should have expired (Low)

**Disposition after design review:** Retained as a specification inconsistency. The architecture describes exact, single-use consent without defining how long it lasts. The [upgradeability plan](../../technical/contract-upgradeability-plan.md) says pending `commitAuthorization` commitments expire after `COMMIT_EXPIRY_BLOCKS`. The code applies that expiry only to the owner's commitment. The intended lifetime of agent consent needs a canonical decision.

`revealAuthorization` checks the owner's commitment against `COMMIT_EXPIRY_BLOCKS` (`contracts/gateway/RobotMoneyGateway.sol:513-527`), then checks only the *existence* of the agent's matching commitment (`:541-545`). `commitAuthorization` stores a block number for both types of commitment (`:505-509`), yet no age check or cancellation path applies to the agent's consent. A consent is bound to a particular owner and exact reveal calldata, so this is a stale-authorization risk rather than arbitrary policy substitution.

**Sequence:** an agent commits consent to owner O and a policy with a long future `validUntil`; O does not complete onboarding. More than 256 blocks later, O makes a fresh owner commitment to the same agent and salt, waits one block, and reveals the original calldata. The old agent consent still satisfies `commitments[ck].committer == agent`, and O becomes `agentOwner` if the address remains unowned. The agent has no exposed way to revoke that consent without controlling O's reveal. The practical impact is unexpected late onboarding and policy ownership for O. A policy whose `validUntil` has passed will be refused by `_validatePolicy` (`:623-630`), which bounds this scenario by the original policy's validity date.

Narrowing condition: while the address remains unowned, the agent can self-authorize it and thereby prevent the owner's later reveal; revoking that agent still does not clear the separate consent commitment. The late reveal remains possible only while the matching policy is valid and the agent has not consumed the address this way. Assess the owner impact under those exact conditions before final severity.

**Recommendation:** enforce the same expiry on the agent's consent commitment and expose cancellation by the committer, or use a signed consent with an explicit deadline and nonce. Add a regression that advances more than 256 blocks, creates a fresh owner commitment, and expects the reveal to fail on the stale agent consent. This finding is based on source reasoning; the exact sequence has not yet been run as a PoC.
